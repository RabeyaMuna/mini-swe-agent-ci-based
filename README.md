# CI-Repair-Bench Evaluation Setup

This repository runs CI repair evaluations for two agents:

- `mini-swe-agent`
- `openhands`

Each agent can be evaluated with two models:

- `openrouter/minimax/minimax-m2.5`
- `openrouter/z-ai/glm-5.2`

Each model is run at four ablation levels:

- `baseline`: no memory
- `L1`: failure memory
- `L1+L2`: failure memory + repository memory
- `L1+L2+L3`: full memory

The evaluation dataset is:

```bash
data/trs/eval_set.jsonl
```

This file is generated by the memory/eval split workflow and contains the full eval issue records. Do not use `data/trs/eval_issue_ids.json` for Mini-SWE-Agent runs because it contains only IDs, not the full issue data.

### 4. API Keys

Configure API keys in the root `.env` file:

```bash
cat > .env <<'EOF'
# MiniMax M2.5 through OpenRouter
OPENROUTER_API_KEY=your_openrouter_key
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1

# GLM through native Z.ai-compatible LiteLLM provider
GLM_API_KEY=your_glm_provider_key

# Optional HuggingFace token, only needed for private/gated dataset access.
# HUGGINGFACE_TOKEN=your_huggingface_token
EOF
```

MiniMax and GLM can use different providers or credentials. The scripts select credentials by model:

- `MODEL=minimax2.5` uses `OPENROUTER_API_KEY` and `OPENROUTER_BASE_URL`.
- `MODEL=glm5.2` uses `GLM_API_KEY` with LiteLLM's native `zai` provider.
- Optional overrides are still supported: set `GLM_MODEL_NAME` if your GLM provider requires a different LiteLLM model string, and set `GLM_BASE_URL` only if your provider does not use the default Z.ai API base.
- Do not set `MEMCI_LLM_MODEL` in `.env` for this workflow. Pass the model explicitly with `MODEL=minimax2.5` or `MODEL=glm5.2`.
- Do not set duplicate MiniMax keys. With the config above, `MINIMAX_API_KEY` and `MINIMAX_BASE_URL` are not needed.

## Model Names

The system supports two models with automatic configuration:

| Model | Full Name | API Provider | Auto-Config |
|---|---|---|---|
| `minimax2.5` | `openrouter/minimax/minimax-m2.5` | `OPENROUTER_API_KEY` / `OPENROUTER_BASE_URL` | 4x increase |
| `glm5.2` | `zai/glm-5.2`, override with `GLM_MODEL_NAME` only if needed | `GLM_API_KEY` | 10x increase |

**Supported aliases:**
- MiniMax: `minimax2.5`, `minimax-m2.5`, `minimax/minimax-m2.5`, `MiniMax-M2.5`
- GLM: `glm5.2`, `glm-5.2`, `z-ai/glm-5.2`, `GLM-5.2`

**Model-Aware Processing:**

When you specify a model, the entire system automatically uses:
- Correct API provider and credentials
- Correct token limits (100k vs 200k input chunks)
- Correct chunk sizes (15 vs 20 L1s per chunk)
- Correct candidate limits (120/160 vs 300/400 L2 candidates)

The same model value is used throughout:
- Memory building (decomposition, L1/L2/L3 generation)
- Cached CI log/workflow analysis
- Memory retrieval and selection
- Agent repair runs (Mini-SWE-Agent and OpenHands)

**See [USAGE_GUIDE.md](USAGE_GUIDE.md) for detailed model specifications.**

## Build Decompositions, Split, And Memory

Use the root environment.

```bash
cd /Users/rabeyakhatunmuna/Documents/mini-swe-agent-ci-based
source .venv/bin/activate
```

### One Command

Run this command for the normal workflow. It handles every required stage:

1. Load issues from HuggingFace, using all repos or the repo filter you pass.
2. Generate decompositions only for issue IDs missing from `data/trs/decomposed_issues.json`.
3. Recompute the cosine-similarity split every run.
4. Build L1/L2/L3 memory only from `data/trs/memory_set.jsonl`.

All repos:

```bash
# MiniMax-M2.5
MODEL=minimax2.5 bash scripts/run_memory_split_workflow.sh

# GLM-5.2
MODEL=glm5.2 bash scripts/run_memory_split_workflow.sh
```

Selected repos:

```bash
# Single repo
MODEL=minimax2.5 bash scripts/run_memory_split_workflow.sh flower

# Multiple repos
MODEL=glm5.2 bash scripts/run_memory_split_workflow.sh flower,agno,camel
```

If no repo is passed, the workflow uses all HuggingFace issues. If repo names are passed, it only fetches and processes those repos.

The workflow uses model-specific limits:

| Model | Decompose files/chunk | Decompose changes/chunk | Output safe tokens | L1 chunk size | L2 candidates |
|---|---:|---:|---:|---:|---:|
| `minimax2.5` | 80 | 400 | 60,000 | 15 | 120 common / 160 consecutive |
| `glm5.2` | 150 | 800 | 120,000 | 20 | 300 common / 400 consecutive |

`data/trs/filtered_issues.jsonl` is only an internal snapshot of the HuggingFace issues selected for the run. You should use the one-command workflow above instead of manually running fetch, decomposition, split, and memory build commands.

### Manual Debug Commands

Use these only to debug or rerun one stage separately. The first decomposition command uses `--skip-memory` intentionally because memory must not be built until after cosine similarity chooses `memory_set.jsonl`; otherwise eval issues would leak into memory.

**1. Fetch dataset from HuggingFace**

```bash
# All repos
python3 scripts/fetch_dataset.py \
  --split train \
  --out data/trs/filtered_issues.jsonl

# Optional: only selected repos
python3 scripts/fetch_dataset.py \
  --split train \
  --out data/trs/filtered_issues.jsonl \
  --repos diffusers,transformers
```

**2. Generate decompositions only**

This creates or updates `data/trs/decomposed_issues.json`. Existing decomposed issue IDs are reused; missing issue IDs are generated.

```bash
# MiniMax-M2.5
python3 scripts/decompose_ci_failure.py \
  --dataset data/trs/filtered_issues.jsonl \
  --output-dir data/trs \
  --model minimax2.5 \
  --skip-memory

# GLM-5.2
python3 scripts/decompose_ci_failure.py \
  --dataset data/trs/filtered_issues.jsonl \
  --output-dir data/trs \
  --model glm5.2 \
  --skip-memory
```

**3. Recompute cosine-similarity split**

Run this every time before rebuilding memory. It rewrites `memory_set.jsonl`, `eval_set.jsonl`, `memory_issue_ids.json`, and `eval_issue_ids.json`.

```bash
python3 scripts/prepare_memory_train_test_split.py \
  --dataset data/trs/filtered_issues.jsonl \
  --output-dir data/trs \
  --memory-ratio 0.3
```

For selected repos:

```bash
python3 scripts/prepare_memory_train_test_split.py \
  --dataset data/trs/filtered_issues.jsonl \
  --output-dir data/trs \
  --memory-ratio 0.3 \
  --repos diffusers,transformers
```

**4. Build L1/L2/L3 memory from the memory set**

This reads `data/trs/memory_set.jsonl`, reuses cached decompositions when available, and writes:

- `data/trs/failure_memory.json`
- `data/trs/repo_memory.json`
- `data/trs/cross_memory.json`

```bash
# MiniMax-M2.5
python3 scripts/decompose_ci_failure.py \
  --dataset data/trs/memory_set.jsonl \
  --output-dir data/trs \
  --model minimax2.5

# GLM-5.2
python3 scripts/decompose_ci_failure.py \
  --dataset data/trs/memory_set.jsonl \
  --output-dir data/trs \
  --model glm5.2
```

```bash

python scripts/evaluate_ablation_preds.py \
  results/miniswe-agent/minimax-m2.5/baseline/preds.json
```

Compare multiple result files:

```bash
source .venv/bin/activate
python scripts/evaluate_ablation_preds.py \
  results/miniswe-agent/minimax-m2.5/baseline/preds.json \
  results/miniswe-agent/minimax-m2.5/L1/preds.json \

  results/miniswe-agent/minimax-m2.5/L1_L2_L3/preds.json
```
